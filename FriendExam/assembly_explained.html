Understanding Assembly Language Programming

A Line-by-Line Guide to the Factorial Program using MASM/TASM

Chapter 1: What is Assembly Language?

Assembly language is a low-level programming language that sits directly above machine code (binary 0s and 1s). Every instruction you write in assembly corresponds almost directly to one instruction the CPU executes.

Unlike high-level languages like Python or Java, in assembly you manually control:

  • Which registers (tiny storage slots inside the CPU) hold your data
  • How data moves between memory and the CPU
  • How arithmetic is performed step by step
  • How the program starts and exits
Analogy: If a high-level language is like driving an automatic car, assembly language is like manually operating every gear, clutch, and engine valve yourself.

Chapter 2: What is MASM / TASM?

MASM (Microsoft Macro Assembler) and TASM (Turbo Assembler by Borland) are tools that translate your assembly code into machine code the CPU can run. They are the standard assemblers taught in Nigerian universities for 16-bit DOS-based assembly programming.

They use the Intel x86 syntax and follow this program structure:

.MODEL  <memory model>
.STACK  <size>
.DATA
    ; your variables here
.CODE
    ; your instructions here

Chapter 3: Key Concepts Before Reading the Code

3.1 Registers

Registers are tiny, ultra-fast storage locations inside the CPU. In 16-bit assembly the main ones are:

RegisterNameCommon Use
AXAccumulatorArithmetic results, general purpose
BXBaseMemory addressing
CXCounterLoop counter
DXDataExtended arithmetic with AX

AX can be split into two 8-bit halves: AH (high byte) and AL (low byte).

3.2 The MUL Instruction

MUL CX multiplies AX by CX and stores the result back in AX. For small numbers like 5! or 6! the result fits in AX.

3.3 The LOOP Instruction

LOOP label does two things automatically:

  • Decrements CX by 1
  • Jumps back to label if CX is not zero

3.4 INT 21H

INT 21H is a DOS interrupt — a way to ask the operating system to perform a service:

AH ValueService
4CHExit the program and return to DOS
09HPrint a string to the screen
01HRead a character from keyboard

3.5 What is Factorial?

The factorial of n (written n!) means multiplying all integers from n down to 1:

5! = 5 × 4 × 3 × 2 × 1 = 120

Chapter 4: Solution 1 — Standalone Factorial Program (Line by Line)

.MODEL SMALL
.STACK 100H

.DATA
NUM     DB 5
RESULT  DW ?

.CODE
MAIN PROC

    MOV AX, @DATA
    MOV DS, AX

    MOV AL, NUM
    MOV AH, 0

    MOV CX, AX
    MOV AX, 1

FACTORIAL_LOOP:
    MUL CX
    LOOP FACTORIAL_LOOP

    MOV RESULT, AX

    MOV AH, 4CH
    INT 21H

MAIN ENDP
END MAIN
LineExplanation
.MODEL SMALL Tells the assembler to use the SMALL memory model — both code and data fit within one 64KB segment each. Most common model for simple DOS programs.
.STACK 100H Reserves 256 bytes (100 in hexadecimal) of memory for the stack. The stack stores data temporarily during procedure calls and interrupts.
.DATA Marks the beginning of the data segment where variables are declared.
NUM DB 5 Declares a variable called NUM. DB means "Define Byte" — stores one byte. Value is 5 (we want to compute 5!).
RESULT DW ? Declares a variable called RESULT. DW means "Define Word" (2 bytes). The ? means uninitialized — we will store the answer here later.
.CODE Marks the beginning of the code segment where instructions are written.
MAIN PROC Declares the start of a procedure named MAIN. This is the entry point of the program.
MOV AX, @DATA Loads the address of the data segment into AX. @DATA is a symbol the assembler replaces with the actual segment address of your .DATA section.
MOV DS, AX Copies AX into DS (Data Segment register). You cannot load DS directly — you must go through AX first. This tells the CPU where your variables live in memory.
MOV AL, NUM Loads the value of NUM (5) into AL — the low byte of AX.
MOV AH, 0 Clears the high byte of AX to 0. This ensures AX = 0005H with no garbage in the upper byte. Now AX = 5.
MOV CX, AX Copies AX (value 5) into CX. CX will serve as the loop counter, counting down from 5 to 1.
MOV AX, 1 Sets AX to 1. AX is our accumulator — holds the running product. We start at 1 because 1 is the identity for multiplication.
FACTORIAL_LOOP: A label — a named marker in the code. The LOOP instruction jumps back here as long as CX is not zero.
MUL CX Multiplies AX by CX, result stored in AX:

Iteration 1: AX = 1 × 5 = 5   (CX becomes 4)
Iteration 2: AX = 5 × 4 = 20   (CX becomes 3)
Iteration 3: AX = 20 × 3 = 60   (CX becomes 2)
Iteration 4: AX = 60 × 2 = 120   (CX becomes 1)
Iteration 5: AX = 120 × 1 = 120   (CX becomes 0)
LOOP FACTORIAL_LOOP Decrements CX by 1 and jumps back to FACTORIAL_LOOP if CX ≠ 0. When CX = 0 the loop ends. AX = 120.
MOV RESULT, AX Stores the final result (120) from AX into the RESULT variable in memory.
MOV AH, 4CH Loads 4CH into AH — the DOS service code for "terminate program".
INT 21H Triggers DOS interrupt 21H. Since AH = 4CH, DOS terminates the program.
MAIN ENDP Marks the end of the MAIN procedure.
END MAIN Tells the assembler this is the end of the source file and that execution begins at MAIN.

Chapter 5: Solution 2 — Factorial as a Called Procedure (Line by Line)

In this version the factorial logic is moved into its own separate procedure called FACTORIAL. The MAIN procedure calls it using the CALL instruction. 

.MODEL SMALL
.STACK 100H

.DATA
NUM     DB 5
RESULT  DW ?

.CODE

MAIN PROC

    MOV AX, @DATA
    MOV DS, AX

    MOV AL, NUM
    MOV AH, 0

    CALL FACTORIAL

    MOV RESULT, AX

    MOV AH, 4CH
    INT 21H

MAIN ENDP


FACTORIAL PROC

    MOV CX, AX
    MOV AX, 1

FACT_LOOP:
    MUL CX
    LOOP FACT_LOOP

    RET

FACTORIAL ENDP

END MAIN
LineExplanation
MOV AL, NUM / MOV AH, 0 Same as Solution 1 — loads n=5 into AX. AX now holds the argument that will be passed to the FACTORIAL procedure.
CALL FACTORIAL Transfers execution to the FACTORIAL procedure. Before jumping, the CPU automatically pushes the return address onto the stack so it knows where to come back. AX (holding 5) is passed as the input.
MOV RESULT, AX After FACTORIAL returns, AX contains the result (120). This saves it to memory.
FACTORIAL PROC Declares the start of a new reusable procedure named FACTORIAL.
MOV CX, AX Inside the procedure, AX holds n (5). Copies it into CX to use as the loop counter.
MOV AX, 1 Resets AX to 1 to begin the multiplication accumulation.
FACT_LOOP: MUL CX / LOOP FACT_LOOP Identical factorial loop as Solution 1. Multiplies AX by CX repeatedly until CX = 0. Result ends up in AX = 120.
RET Returns from the procedure back to MAIN. The CPU pops the return address from the stack and jumps back to the instruction after CALL FACTORIAL. AX still holds 120.
FACTORIAL ENDP Marks the end of the FACTORIAL procedure.

Chapter 6: How CALL and RET Work Together

When the CPU executes CALL FACTORIAL:

  1. It saves the address of the next instruction (after CALL) onto the stack.
  2. It jumps to the FACTORIAL procedure.
  3. The procedure runs and computes the result in AX.
  4. When RET is reached, the CPU retrieves the saved address from the stack.
  5. Execution resumes in MAIN at MOV RESULT, AX.
This is why the stack exists. Without it, the CPU would have no way of knowing where to return after a procedure call.
